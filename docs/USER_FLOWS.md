# User flows

## Implemented learner flow (M1–M3)
Register/login → describe learning objective, level, skills, format, schedule, budget, and duration → save as draft or publish an open request → discover/filter open requests → view request details → save requests → manage, edit, publish, or close owned requests → open received proposals → compare applicant profile, approach, experience, schedule, duration, and price unit → download an attached CV through the authorized endpoint.

Selection/matching, messaging, and feedback are future milestones.

## Implemented developer proposal flow
Register → create professional profile → browse open requests → submit one active teaching proposal per request → upload/select a private PDF CV when required or desired → edit or withdraw a submitted proposal → manage CV files. Closing a request prevents new submissions; prior proposals remain available to participants.

## Future developer flow
Agree on selected proposal → conduct sessions → receive feedback. Selection and matching are M4.

## Target moderation flow
Review user reports → inspect relevant content under moderator authorization → take documented moderation action → preserve audit event.

## M0 implementation
The M0 landing shell used explicitly illustrative examples. M2 replaces discovery examples with API-backed request results. Registration/profile, requests, proposals, and CV operations call the API; matching, sessions, and moderation remain unimplemented.
