# User flows

## Implemented learner flow (M1–M2)
Register/login → describe learning objective, level, skills, format, schedule, budget, and duration → save as draft or publish an open request → discover/filter open requests → view request details → save requests → manage, edit, publish, or close owned requests.

Proposals, applicant comparison, matching, messaging, and feedback are future milestones.

## Target developer flow
Register → create professional profile → browse open requests → submit one active teaching proposal per request → attach CV only if needed/desired → respond to learner → conduct agreed sessions → receive feedback.

## Target moderation flow
Review user reports → inspect relevant content under moderator authorization → take documented moderation action → preserve audit event.

## M0 implementation
The M0 landing shell used explicitly illustrative examples. M2 replaces discovery examples with API-backed request results. Registration/profile and request workflows call the API; proposals, matching, sessions, and moderation remain unimplemented.
